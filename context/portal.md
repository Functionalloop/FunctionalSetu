# Portal

The web portal (React + TypeScript + Vite, TanStack Query) is the teammate's part, but **if the teammate cannot deliver, I build it** (decided 11 Nov). It calls the REST API live; it does not sync.

## Contract

- `docs/openapi.json` is the contract (generated by `scripts/export_openapi.py`, checked by a test). Generate the TypeScript client from it; operation ids are the Python function names and stable.
- Since 4.10 **every endpoint exists**: 16 built, 82 answer `501 not_implemented` with final request/response shapes. A portal screen can be built against the shapes now and starts working when its plan task is built.
- `tests/test_contract.py`: every endpoint in `docs/02_tech_stack_and_api.md` is in the API, except saved filters (not in the SRS). Additions beyond the document (plan gap-table proposals): `GET /files/{id}`, `POST /mobile-imports/{id}/rows/{row_id}/resolve`.
- `/masters/{list}` is served as explicit routes per list (`/masters/castes`, `/masters/professions`, `/masters/color-tags`, `/masters/custom-fields/{field_key}`, `/masters/message-templates/{kind}`).
- Errors: `{"error": {"code", "message", "details"?, "current"?}}`; the code table is in the OpenAPI description. 409 `version_conflict` carries `error.current` (server copy).
- Lists: `?limit=&cursor=` → `{items, next_cursor}`. Dates UTC; show Indian time.
- Rule: any contract change goes into OpenAPI first; tell the teammate the same day. Add fields, never break.
